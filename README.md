# ClinicHub Frontend — Requirements

## Dynamic Reservation Slot Duration (مدة الحجز الديناميكية)

### Goal

The booking slot duration is **per (doctor, day)** — each availability row carries its own
`slotDurationMinutes`. All dashboards must reflect the **same live data** from the backend API and
must **never** display a static/hard-coded duration as the source of truth.

Backend contract: `docs/doctor-availability-api.md`

---

### 1. Doctor Dashboard — Availability page (`Views/Doctor/Availability.cshtml`)

| # | Requirement | Status |
|---|-------------|--------|
| 1.1 | Load the doctor's weekly schedule on page load via `GET /api/v1/doctors/availability` (doctor resolved from token — no `doctorId` sent) | ✅ Done |
| 1.2 | Render one row per availability entry: day, start time, end time, slot duration input (minutes, `1`–`480`, default `30`) | ✅ Done |
| 1.3 | Allow multiple rows on the same day (e.g. morning + evening) | ✅ Done |
| 1.4 | Allow adding / removing rows | ✅ Done |
| 1.5 | Save the whole week via `PUT /api/v1/doctors/availability/week` — existing rows keep their `id`, new rows omit it; rows removed from the grid are soft-deleted by the backend | ✅ Done |
| 1.6 | After save, re-render the grid from the API response (fresh ids) | ✅ Done |
| 1.7 | "Typical duration" badge + stat card = most frequent `slotDurationMinutes` across the grid, recomputed **live** on every edit / add / remove | ✅ Done |
| 1.8 | Empty schedule (`data: []`) → seed editable default rows (Sun–Thu, 09:00–17:00, 30 min) so the page is never empty | ✅ Done |
| 1.9 | API failure → show error banner, keep page usable (never crash) | ✅ Done |
| 1.10 | Seeded rows must carry no `id` (empty-GUID ids must be ignored on save to avoid 404) | ✅ Done |

### Validation rules (from the API contract)

| Field | Rule |
|-------|------|
| `dayOfWeek` | Valid `DayOfWeek` 0–6 |
| `startTime` | Required (`HH:mm:ss`) |
| `endTime` | Required, must be **after** `startTime` |
| `slotDurationMinutes` | `1`–`480`, default `30` |
| `id` (week payload) | If provided, must belong to the logged-in doctor (`404` otherwise) |

### Non-functional requirements

- Arabic RTL UI; design tokens (`var(--clr-*)`, `var(--space-*)`, …) — **no hard-coded colors/spacing**
- **No inline `style=""`** in CSHTML — CSS classes only (`site.css` / `design-system.css`)
- Controllers pass data via `ViewBag` only — no business logic, no `@model` directives
- **Never touch** `wwwroot/js/*.js` — page scripts stay inline in views
- `dotnet build` (ClinicHub/ClinicHub.csproj) must pass with 0 errors

### Acceptance criteria

1. A doctor edits a day's slot duration (e.g. 45 min) and saves → the schedule page reloads with 45 min for that day.
2. The clinic settings page shows the **typical** (most frequent) duration across all doctors — read-only, updates when doctor schedules change.
3. The clinic doctors page shows each doctor's per-day durations from live data.
4. No static/hard-coded duration is shown anywhere as authoritative.
5. All pages degrade gracefully (fallback / error banner) without crashing.
