الخطوات العملية
1) ضيفي الـ MCP servers (أمر واحد لكل واحد في التيرمنال)
bash
opencode mcp add sequential-thinking -- npx -y @modelcontextprotocol/server-sequential-thinking

opencode mcp add semgrep -- uvx semgrep-mcp

opencode mcp add github -- npx -y @modelcontextprotocol/server-github

opencode mcp add playwright -- npx -y @playwright/mcp
2) أو حطيهم كلهم مرة واحدة في opencode.json (جوه مجلد المشروع)
json
{
  "mcp": {
    "sequential-thinking": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-sequential-thinking"],
      "enabled": true
    },
    "semgrep": {
      "type": "local",
      "command": ["uvx", "semgrep-mcp"],
      "enabled": true
    },
    "github": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-github"],
      "enabled": true
    },
    "playwright": {
      "type": "local",
      "command": ["npx", "-y", "@playwright/mcp"],
      "enabled": false
    }
  }
}

ملاحظة: خليتلك playwright: enabled: false كمثال — فعّليه بس وقت ما تعملي performance test فعليًا، عشان توفري context tokens زي ما اتكلمنا.

3) اعملي الـ subagents (ملفات Markdown)

جوه مجلد .opencode/agent/ (أو ~/.config/opencode/agent/ للـ global) اعملي ملفين:

.opencode/agent/reviewer.md

markdown
---
description: يراجع الكود بعد كل build زي senior engineer
mode: subagent
---
راجع الـ diff الأخير وركّز على: bugs محتملة، edge cases ناقصة،
naming واضح، تكرار كود ممكن يتلغى، وتوافق مع باقي كود المشروع.
اديني ملاحظاتك كـ bullet points، ومتعدليش الكود إلا لو طلبت منك صراحةً.

.opencode/agent/security-reviewer.md

markdown
---
description: يراجع الكود من ناحية الأمان زي مهندس أمن
mode: subagent
---
راجع الـ diff الأخير بعقلية مهندس أمن: auth logic، input validation،
permissions/access control، exposure لبيانات حساسة، وأي منطق
ممكن يتستغل حتى لو مفيش pattern معروف. اربطه بنتيجة Semgrep لو موجودة
وكمّلها بحاجات المنطق اللي الأدوات الثابتة مش بتشوفها.
4) الـ workflow اليومي بتاعك
1. Tab → Plan mode → اكتبي المهمة → opencode يحط خطة
2. Tab → Build mode → ينفذ
3. @reviewer → مراجعة كود عامة
4. @security-reviewer → مراجعة أمان
5. شغّلي Semgrep يدويًا أو عبر custom command: opencode run "افحص آخر تغييرات بـ semgrep"
6. لو حسّاسة/API: فعّلي playwright وقتها وشغّلي k6 عبر shell command عادي
5) لو عايزة تختصري كل ده في أمر واحد

اعملي custom command في .opencode/command/full-check.md:

markdown
---
description: تشغيل كل الفحوصات مرة واحدة
---
شغّل Semgrep على آخر التغييرات، بعدين استدعي @reviewer و@security-reviewer،
واديني تقرير موحد بالمشاكل مرتبة حسب الأهمية.

وبعدين تكتبي بس /full-check في opencode وهو يعمل كل حاجة.

عايزاني أضبطلك أوامر الـ custom command لتشغيل k6 أو Lighthouse تلقائيًا كمان، ولا كفاية كده كبداية؟

طب ازاي اعمل markdown لكل subagent هشغله؟؟؟؟

عادي، خطوة بخطوة من غير تعقيد:

اعملي المجلد المناسب لو مش موجود
من جوه مجلد المشروع بتاعك (مش مهم فين بالظبط داخل opencode، بس لازم تكوني فاتحة المشروع في التيرمنال): mkdir -p .opencode/agent المجلد ده لو مش موجود هيقولك mkdir ويعمله عادي جديد، مش حاجة تعملي حاجة تانية.

خلاصة سريعة عشان تفتكري:

ملف واحد = subagent واحد
المكان: .opencode/agent/اسم-الايجنت.md
اسم الملف (من غير .md) = الاسم اللي هتناديه بيه بـ @
الشكل: --- description + mode: subagent --- ثم الـ prompt

تحب حاجة عملية: بدل ما تكتبي الملفات يدويًا، ممكن تقولي لـ opencode نفسه وهو مفتوح: "اعملي subagent اسمه reviewer بيراجع الكود بعد كل build" وهو غالبًا هيعرف يعمل الملف صح لوحده لأنه فاهم بنية نفسه.

عايزاني أكتبلك محتوى الملفين كاملين (reviewer.md و security-reviewer.md) جاهزين تعمليهم copy-paste على طول؟
