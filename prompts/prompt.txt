Short answer: no — on your host, web.config will be ignored, so don't put it there.

Why not

web.config environment variables only work when IIS (the ASP.NET Core Module) launches your app. Your host doesn't use IIS — your own server log proves it: the app boots as dotnet ClinicHub.dll with Kestrel binding straight to http://127.0.0.1:5000. In that mode web.config is never read. Adding it would change nothing and just mislead the next person.

This also tells you something important: the port must be set where the panel's proxy can see it — i.e., in the panel itself (env var or port field), because the proxy routes each domain to its site's configured port. A value hidden in your repo files can't steer the proxy.

So where exactly — one more look

In your panel, open the WebDashboard site settings (the doctory-001-site2 site) and look for any one of these:

- Environment Variables → add ASPNETCORE_URLS = http://127.0.0.1:5000

- Port field → enter 5000 (and 5001 on the ApiSite)

- Startup command (dotnet ClinicHub.dll) → change to dotnet ClinicHub.dll --urls http://127.0.0.1:5000

Same for ApiSite, with port 5001. Then Stop → Start both sites and check the log for Now listening on: http://127.0.0.1:5000 with no address already in use.

If none of those exist in your panel
