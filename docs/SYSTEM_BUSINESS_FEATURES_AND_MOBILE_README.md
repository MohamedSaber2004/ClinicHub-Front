## 2. أدوار المستخدمين والصلاحيات (User Roles & Personas)

1. **`SystemAdmin` (سوبر أدمن المنصة):** الرقابة الكاملة على العيادات، تدقيق المستندات، إدارة الباقات والاشتراكات، متابعة الإيرادات والمدفوعات، وإدارة كتالوج التخصصات والإعلانات.
2. **`ClinicOwner` (مالك العيادة):** إدارة العيادة، شراء وإدارة الاشتراكات، شراء الباقات الإعلانية، متابعة تقارير وإيرادات العيادة، إدارة الطاقم والأطباء وضبط إعدادات الحجز والكشف.
3. **`ClinicStaff` / `ClinicManager` (موظف الاستقبال وطاقم العيادة):** إدارة طابور الانتظار اليومي (Queue)، تسجيل وصول المرضى (Check-in)، قبول/رفض طلبات الحجز، وتسجيل المرضى الجدد مباشرة بالعيادة (Walk-in).
4. **`Doctor` (طبيب العيادة):** استعراض المواعيد اليومية، فحص سجل المرضى والتشخيصات السابقة، كتابة الملاحظات الطبية، وتحديد وتحديث أوقات العمل الأسبوعية (Availability).
5. **`Patient` (المريض — عبر تطبيق الموبايل):** تصفح الأطباء والعيادات، حجز المواعيد المؤتمت، الدفع الإلكتروني (بطاقات ومحافظ)، التقييم الثلاثي للخدمة، المحادثة الفورية، والتفاعل مع مجتمع المنصة.

## 3. الفهرس الشامل لجميع الميزات المنفذة (Implemented Business Features)

### 3.1 انضمام وتوثيق العيادات (Clinic Onboarding & Verification)
- **معالج تسجيل العيادة (Wizard):** 3 خطوات تفاعلية (بيانات العيادة الأساسية ← رفع الوثائق والتراخيص الرسمية ← تحديد الموقع الجغرافي الدقيق عبر Google Maps مع مراجعة شاملة).
- **متابعة دورة التسجيل (Tracking Ticket):** تتبع حالة الطلب عبر 4 مراحل (تم الاستلام ← قيد المراجعة ← الموافقة ← التفعيل).
- **مركز التحقق للأدمن (Verification Center):** مراجعة مستندات العيادات واعتمادها أو رفضها مع كتابة سبب الرفض وإشعار المالك فورياً.
- **بوابة التفعيل والاشتراك الإلزامي:** تحويل المالك المعتمد لبوابة التفعيل مع فرض وجود باقة نشطة للدخول إلى لوحة التحكم.

### 3.2 المصادقة وإدارة الحسابات (Authentication & Identity)
- **حماية JWT كاملة:** Access Token + Refresh Token مع إدارة انتهاء الجلسات بأمان.
- **تسجيل الدخول الاجتماعي (Mobile SSO):** دعم تسجيل الدخول والتسجيل عبر **Google** و **Facebook** في الـ Backend وتطبيق الموبايل.
- **استعادة الحساب عبر البريد:** دورة كاملة (طلب استعادة ← توليد رمز OTP من 6 أرقام ← التحقق من الرمز ← تعيين كلمة مرور جديدة).
- **إدارة الملف الشخصي:** تعديل الاسم، رقم الهاتف، تاريخ الميلاد، النوع، ورفع الصورة الشخصية (Avatar).
- **نظام الصلاحيات الديناميكي:** استخدام نمط Flags Enum للتحكم الدقيق بصلاحيات المديرين والموظفين.

### 3.3 الاشتراكات والباقات (B2B Subscriptions & Billing)
- **كتالوج الباقات (Plan Catalog):** باقات شهرية وسنوية متعددة المستويات، تحدد الحد الأقصى للأطباء والموظفين والميزات المتاحة.
- **عزل الميزات وحمايتها (Feature Gating):** حجب الوصول للميزات الإضافية (مثل الحملات الإعلانية والتقارير المتقدمة) إلا بعد ترقية الباقة.
- **الاشتراك عبر بوابة الدفع (Paymob):** إتمام دفع الاشتراك أونلاين، التحقق من الدفع، والتفعيل التلقائي الفوري، مع إمكانية إلغاء الاشتراك.
- **إدارة الاشتراكات للأدمن:** إمكانية منح وتفعيل اشتراك يدوي للعيادة وحساب القيمة تلقائياً، وإلغاء/تجديد الاشتراكات القائمة.
- **إعدادات حجز العيادة (Clinic Reservation Settings):**
  - رسوم الكشف (`consultationFee`).
  - العملة (`currency`).
  - أقصى أيام للحجز المسبق (`maxAdvanceBookingDays` — افتراضي 30 يوماً).
  - مهلة تثبيت الحجز قبل السداد (`reservationTtlMinutes` — 10 دقائق).
  - مهلة نافذة الإلغاء المسموحة للمريض (`cancellationWindowMinutes` — 120 دقيقة).

### 3.4 المدفوعات والعمليات المالية (Payments & Financial Operations)
- **دعم وسائل دفع Paymob:**
  1. **البطاقات الائتمانية (Paymob Credit Card / Visa / MasterCard)**.
  2. **المحافظ الإلكترونية (Paymob Wallets - فودافون كاش / أورنج / اتصالات كاش)**.
  3. **الدفع النقدي في العيادة (Cash)**.
- **معالجة العمليات المالية للأدمن:**
  - تصفية وبحث المدفوعات (حسب نوع الدفع: كشف / اشتراك / إعلان، والحالة: معلق / ناجح / فاشل / مسترد).
  - تفاصيل العملية وجدول زمني دقيق لكل حركة مالية (Payment Timeline).
  - إمكانية استرداد الأموال للعمليات الناجحة (Refund) مع توثيق السبب.
  - تسجيل دفعات نقدية أو يدوية للاشتراكات (Manual Payments).
  - معالجة الـ Webhooks من Paymob بشكل متزامن وغير قابل للتكرار (Idempotency).

### 3.5 الإعلانات والتسويق (Ads & Marketing Engine B2B)
- **من جانب العيادة:** استعراض باقات الإعلانات، حاسبة السعر المباشر (سعر الباقة × المدة)، الدفع الفوري عبر Paymob، ومتابعة حالة الإعلانات (نشط، منتهي، معلق).
- **من جانب الأدمن:** إدارة باقات الإعلانات (CRUD)، إنشاء طلبات إعلانية للعيادات المؤهلة، وإيقاف أو إلغاء الإعلانات المخالفة مع ذكر السبب.
- **من جانب الموبايل:** توفير API عام (`PublicAdsController`) لعرض الإعلانات النشطة للمرضى داخل تطبيق الموبايل.

### 3.6 محرك المواعيد وجدول الحجوزات (Appointments & Scheduling)
- **دورة حياة الموعد (Appointment Lifecycle):**
  `Pending` (معلق) ➔ `Reserved` (محجوز ومؤقت لمدة 10 دقائق) ➔ `Accepted` (مقبول بانتظار السداد) ➔ `Confirmed` (مؤكد ومدفوع) ➔ `CheckIn` (وصول للعيادة) ➔ `Completed` (مكتمل)، بالإضافة لحالات `Cancelled` (ملغي)، `Rejected` (مرفوض)، و `NoShow` (لم يحضر).
- **مدة الكشف الثابتة (Fixed Slot Duration):** مدة الكشف موحدة بـ 30 دقيقة عبر النظام والأطباء.
- **قواعد الإلغاء:** رفض الإلغاء عبر API في حال كان المتبقي على الموعد أقل من نافذة الإلغاء المحددة (120 دقيقة).
- **تقسيم الإيرادات:** احتساب رسوم الكشف ونسبة المنصة تلقائياً لكل حجز.

### 3.7 إدارة الاستقبال وطابور المرضى (Staff Operations & Queue)
- **طابور المرضى الحي (Live Queue):** استعراض قائمة الحضور اليومية في العيادة، تسجيل وصول المريض (`Check-in`)، وتأكيد انتهاء الكشف.
- **التعامل مع طلبات الحجز:** قبول الحجز (مع تحديد وسيلة الدفع والرابط) أو رفض الحجز مع ذكر الملاحظات.
- **تسجيل المرضى الحاضرين (Walk-in Registration):** إنشاء ملف مريض جديد بالاستقبال مباشرة وحجزه فورياً دون حاجة لتطبيق الموبايل.
- **متابعة جداول الأطباء:** استعراض مواعيد وأيام تواجد جميع أطباء العيادة.

### 3.8 لوحة الطبيب وساعات العمل (Doctor Clinical Dashboard)
- **محرر أوقات العمل الأسبوعي (Weekly Availability Grid):** تحديد مواعيد وأيام وساعات العمل وحفظها بنظام (Week-replace) لكل طبيب.
- **إدارة الحالات الطبية ومواعيد الطبيب:** تغيير حالة الموعد، استعراض الشكوى، وتدوين الملاحظات السريرية والتشخيص.
- **سجل المرضى وتاريخ الزيارات السابقة (Medical History):** استعراض تاريخ زيارات كل مريض والتشخيصات السابقة.

### 3.9 السجلات الطبية والملف الصحي (EMR & Medical Records)
- حفظ بيانات الشكوى المرضية والأمراض المزمنة للمريض (`Complaint` & `ChronicDiseases`).
- أرشفة التشخيصات والملاحظات الطبية لكل زيارة.
- توفير واجهات برمجية لاستعراض المريض لسجلاته عبر تطبيق الموبايل.

### 3.10 نظام التقييمات والمراجعات (Ratings & Reviews)
- **تقييم ثلاثي الأبعاد منفصل (3-Dimensional Ratings):**
  1. تقييم أداء الطبيب (`Doctor Rating`).
  2. تقييم العيادة والخدمة (`Clinic Rating`).
  3. تقييم نظافة المكان والاستقبال (`Place Cleanliness & Reception Rating`).
- **إرسال التقييم:** يتم حصرياً عبر تطبيق الموبايل بعد إتمام الكشف بنجاح.
- **عرض التقييمات:** قراءة التقييمات ومتوسطات النجوم والمراجعات التفصيلية في لوحات الويب للعيادة والطبيب.

### 3.11 المحادثات الفورية والربط اللحظي (Real-Time Chat via Pusher)
- محادثات فورية بين المرضى والعيادات/الأطباء مبنية على **Pusher WebSockets**.
- دعم حالات: إرسال الرسائل، قراءة الرسائل، مؤشر الكتابة (`Typing Indicator`)، وحالة الاتصال (`Online Status`).
- تسليم الرسائل المعلقة للمستخدمين غير المتصلين عند إعادة الفتح.

### 3.12 مجتمع المنصة والمنشورات (Community Posts & Comments)
- شبكة اجتماعية طبية مصغرة داخل التطبيق:
  - نشر المقالات والمنشورات الطبية (`Posts`).
  - إضافة التعليقات والردود عليها (`Comments & Replies`).
  - التفاعل بالإعجاب والتفاعلات (`Toggle Reactions`).

### 3.13 الإشعارات الفورية (FCM Notifications & Web Push)
- **18 نوع إشعار مدعوم بالنظام:**
  (رسالة محادثة جديدة، قرب انتهاء اشتراك، قرب انتهاء إعلان، موعد خارج وقت العمل، طلب حجز جديد، تسجيل عيادة، قبول/رفض عيادة، تحديث تذكرة دعم، استلام دفعة مالية، زيادة إيرادات... إلخ).
- تسجيل وتحديث الـ FCM Token تلقائياً في الويب والموبايل.
- إرسال إشعارات الهاتف (Push Notifications) مع روابط عميقة (Deep Links) تنقل المستخدم مباشرة للهدف.
- مركز إشعارات متكامل في شريط أدوات الويب (Notification Bell) مع عداد الإشعارات غير المقروءة.

### 3.14 كتالوج التخصصات الطبية (Specializations Catalog)
- إدارة التخصصات الطبية (إضافة، تعديل، حذف، وأيقونة مخصصة لكل تخصص).
- فلترة الأطباء والعيادات حسب التخصص في البحث عبر الموبايل وتسجيل العيادات.

## 4. دليل وظائف تطبيق الموبايل (Mobile Application Capabilities)

تطبيق الموبايل مصمم خصيصاً للمرضى والمجتمع الطبي ومربوط بالكامل مع الـ Backend APIs:

| الوظيفة في تطبيق الموبايل | مسار الـ API المقابل في الـ Backend | الوصف ودورة العمل |
|---|---|---|
| **تسجيل الدخول والتسجيل** | `POST /api/v1/auth/login`<br>`POST /api/v1/auth/google`<br>`POST /api/v1/auth/facebook` | تسجيل الدخول بالبريد أو عبر حسابات Google / Facebook واستلام JWT Token. |
| **البحث عن العيادات والأطباء** | `GET /api/v1/clinics`<br>`GET /api/v1/doctors`<br>`GET /api/v1/specializations/active` | تصفح وبحث هجين (Hybrid Search) وفلترة حسب التخصص والمسافة الجغرافية والتقييم. |
| **استعراض أوقات الكشف المتاحة** | `GET /api/v1/clinics/{clinicId}/doctors/{doctorId}/slots?date=...` | جلب الفترات المتاحة للطبيب (30 دقيقة لكل حصة) بناءً على جدول عمل الطبيب. |
| **حجز موعد مبدئي (Reserve Slot)** | `POST /api/v1/booking/reserve` | حجز الحصة مؤقتاً وتثبيتها لمدة 10 دقائق (TTL Hold) لحين إتمام الدفع. |
| **سداد رسوم الكشف** | `POST /api/v1/payments/initiate`<br>`POST /api/v1/payments` | فتح رابط Paymob للدفع عبر البطاقة الائتمانية أو المحفظة الإلكترونية (Vodafone Cash / Orange / Etisalat). |
| **إشعارات الهاتف المباشرة** | `POST /api/v1/notifications/fcm-token` | تسجيل رمز FCM Token للهاتف لاستقبال التحديثات اللحظية والتنبيهات بروابط مباشرة. |
| **المحادثة اللحظية (Chat)** | `POST /api/v1/conversations/.../messages`<br>`POST /api/v1/realtime/pusher/auth` | شات مباشر مع العيادة/الطبيب مدعوم بـ Pusher WebSockets مع مؤشرات الكتابة. |
| **منشورات المجتمع والتفاعل** | `GET/POST /api/v1/posts`<br>`POST /api/v1/posts/{id}/reactions`<br>`POST /api/v1/comments` | تصفح المنشورات الطبية، الإعجاب، وإضافة التعليقات والردود. |
| **تقييم الزيارة بعد الكشف** | `POST /api/v1/ratings` | إرسال التقييم الثلاثي (الطبيب + العيادة + نظافة واستقبال المكان) بعد انتهاء الموعد. |
| **ملف المريض ومواعيده السابقة** | `GET /api/v1/appointments/my`<br>`GET /api/v1/auth/profile` | متابعة حالة المواعيد (مؤكدة، قيد الانتظار، منتهية) واستعراض الملف الطبي. |

## 6. أهم القواعد البرمجية وقواعد العمل (Key Business Rules)

1. **مدة الحصة الثابتة (30 Minutes):** كل موعد كشف محدد بـ 30 دقيقة ثابته ولا تتغير تلقائياً في كافة العيادات والأطباء.
2. **مهلة تثبيت الحجز (TTL = 10 Minutes):** عند بدء حجز مقعد، يتم حجزه كـ `Reserved` لمدة 10 دقائق، وإذا لم يُسدد يتم إلغاؤه تلقائياً وإتاحته للآخرين.
3. **نافذة الإلغاء (Cancellation Window = 120 Minutes):** لا يمكن للمريض إلغاء الحجز عبر التطبيق إذا تبقى أقل من ساعتين (120 دقيقة) على موعد الكشف (`Booking.CancellationWindowExpired`).
4. **تأكيد بوابة الدفع (Paymob Webhooks):** كل عملية دفع يتم تحديثها بناءً على الـ Webhook الرسمي لضمان أمان العمليات وعدم التلاعب.
5. **التقييم الثلاثي:** لا يمكن إرسال التقييم إلا لموعد بحالة مكتمل `Completed`، ويشمل إجبارياً تقييم الطبيب والعيادة والنظافة.
