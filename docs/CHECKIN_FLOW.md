# تسجيل وصول (Check-In) — شرح المنطق والتدفق لفريق الواجهة

> وثيقة تشرح منطق "تسجيل وصول المريض" في الـ API، وما الذي تغيّر، وما الذي يجب أن تظهره الواجهة لكل حالة موعد.

---

## المشكلة (ما كان خطأً)

الـ API كان يسمح بتسجيل الوصول **فقط** عندما تكون الحالة `Confirmed` (مدفوع). لكن سير العمل الفعلي للعيادة هو: **تسجيل مريض → قبول العيادة → دخول المريض** — وغالبًا بدون دفع إلكتروني. لذلك كان زر "تسجيل وصول" يفشل دائمًا، لأن موعد المريض الجديد لا يكون أبدًا `Confirmed`.

---

## تدفق حالات الموعد

```
المريض يحجز أونلاين أو يُسجل
        │
        ▼
┌── العيادة لها رسوم كشف؟ ──► RESERVED (يُحجز الموعد بانتظار الدفع)
│                             │ دفع → CONFIRMED
│                             │ انتهاء المهلة → CANCELLED
│
└── مجاني / يدوي ──► PENDING (بانتظار موافقة العيادة)
                      │ العيادة تقبل → ACCEPTED (بانتظار الدفع)
                      │ العيادة ترفض  → REJECTED
                      │ دفع → CONFIRMED

ACCEPTED أو CONFIRMED ──► تسجيل وصول ✅ (متاح الآن)
CONFIRMED ──────────────► COMPLETED (انتهت الزيارة)
                          ─► NO-SHOW (لم يحضر المريض)
```

---

## التغيير الذي تم (Backend)

| | القاعدة القديمة | القاعدة الجديدة |
|---|---|---|
| تسجيل الوصول مسموح عندما تكون الحالة | `Confirmed` فقط | `Confirmed` **أو** `Accepted` |
| ما زال ممنوعًا | — | `Pending` (لم تتم الموافقة)، `Reserved` (الدفع لم يبدأ)، `Cancelled`، `Rejected`، `Completed`، `NoShow` |

الكود الحالي في `CheckInPatientCommandHandler`:

```csharp
if (appointment.Status is not (AppointmentStatus.Confirmed or AppointmentStatus.Accepted))
    throw ... // "لا يمكن الرد على هذا الموعد"
```

---

## ما يجب أن تظهره الواجهة لكل حالة

| الحالة | الاسم العربي | زر تسجيل الوصول |
|---|---|---|
| `Accepted` | مقبول / بانتظار الدفع | ✅ **إظهار** — يعمل الآن |
| `Confirmed` | مؤكد | ✅ **إظهار** |
| `Pending` | بانتظار التأكيد | ❌ إخفاء — يجب أن تقبل العيادة أولًا |
| `Reserved` | محجوز / بانتظار الدفع | ❌ إخفاء — يجب أن يبدأ المريض الدفع |
| `Cancelled` / `Rejected` | ملغي / مرفوض | ❌ إخفاء |
| `Completed` / `NoShow` | مكتمل / لم يحضر | ❌ إخفاء |

---

## تدفق الـ Backend عند الضغط على الزر

1. `POST /api/v1/staff/appointments/{id}/check-in` → `CheckInPatientCommandHandler`
2. التحقق أن الموعد يخص عيادة المستخدم المسجّل الدخول → وإلا `NotAuthorizedToRespond`
3. التحقق أن الحالة `Accepted` أو `Confirmed` → وإلا `CannotRespondAppointment` (الخطأ الذي كنت تراه)
4. `appointment.CheckIn()` → تصبح الحالة `Confirmed` → يظهر المريض في طابور اليوم مباشرة

---

## ملاحظات للواجهة

- **تسجيل مريض walk-in** (`RegisterWalkInPatient`) يسجّل الوصول تلقائيًا ويجعل الحالة `Confirmed` مباشرة — لا حاجة لضغطة ثانية.
- إذا ما زال الخطأ يظهر لمريض جديد: الموعد لا يزال في `Pending` أو `Reserved` — يجب أن **تقبل العيادة الموعد أولًا** (أو يكمل المريض الدفع)، ثم يعمل تسجيل الوصول.
- **الكود القديم = القاعدة القديمة**: التغيير يجب أن يُنشر (Deploy) على السيرفر حتى يسري مفعوله.
